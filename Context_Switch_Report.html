Abstract

Context Switch is an educational desktop application that simulates CPU process scheduling and visualizes the behavior of scheduling algorithms. It accepts manually entered or randomly generated process datasets and executes six scheduling policies using a common process model.

The project objectives are to demonstrate FCFS, SJF, SRTF/SRTN, non-preemptive Priority, preemptive Priority, and Round Robin scheduling; calculate completion, turnaround, waiting, weighted turnaround, and CPU utilization metrics; display Gantt charts; and compare algorithms using the same workload.

The completed system provides independent scheduler implementations, centralized metric calculation, random-data preview and validation, algorithm ranking, winner detection, comparison tables, and dedicated performance graphs. The implementation is validated by an automated test suite with 33 passing tests and assignment-style scheduling examples.

1. Introduction

Background and Context

CPU scheduling is the operating-system activity of selecting a ready process for execution. Different policies produce different waiting and turnaround behavior even when the process workload is identical. Visualization makes these differences easier to understand than formulas alone.

Problem Statement

Students often calculate scheduling timelines manually but do not have a single tool that clearly connects ready-queue decisions, preemption, idle periods, Gantt charts, and performance metrics. The project solves this problem with a reusable simulation and visualization application.

Objectives and Scope

  • Support six standard scheduling cases independently.
  • Preserve the same input dataset across algorithm comparisons.
  • Show process-level and average scheduling metrics.
  • Visualize execution intervals, preemption, switching, and idle time.
  • Provide manual entry and controlled random process generation.
  • Keep scheduling logic independent from the Tkinter interface.

Importance of the Project

The system connects operating-systems theory with observable execution. It also demonstrates software engineering practices including modular design, input validation, independent testability, and separation of concerns.

2. System Requirements

Functional Requirements

  • Create, validate, remove, and clear process records.
  • Generate random processes within user-defined ranges, with optional seed.
  • Run FCFS, SJF, SRTF/SRTN, Priority NP, Priority P, and Round Robin.
  • Configure the Round Robin quantum.
  • Calculate CT, TAT, WT, WTT, averages, and CPU utilization.
  • Display an eight-column process results table and Gantt chart.
  • Compare all six algorithms using independent copies of one dataset.
  • Rank algorithms and identify overall and individual metric winners.
  • Display batch comparison charts in a dedicated Performance Graphs tab.

Non-Functional Requirements

  • Correctness according to the assignment tie-breaking conventions.
  • Maintainability through modular Python components.
  • Usability through validation messages and readable tables.
  • Reliability through automated unit tests and immutable source inputs.
  • Portability across systems supporting Python, Tkinter, and Matplotlib.

3. Implementation

Architecture and Modules

ModuleResponsibility

gui/performance.pyProvides the Algorithm Comparison and Performance Graphs views.

Scheduling and Metric Integration

Each scheduler receives a list of Process objects through the common Scheduler interface. The interface validates the input and creates independent process copies before execution. Schedulers return a SimulationResult containing completed process records and timeline segments. The metrics engine then calculates:

TAT = CT - AT
WT = TAT - BT
WTT = TAT / BT
CPU Utilization = Busy Time / Total Elapsed Time × 100

The comparison service invokes every scheduler with the same original dataset and the same Round Robin quantum. It ranks average WT, TAT, and WTT equally; CPU utilization is reported separately and is not included in the overall ranking score.

Graphical Integration

The Simulation tab presents one selected algorithm. The Algorithm Comparison tab presents the batch summary and winner analysis. The Performance Graphs tab separately presents average WT, average TAT, average WTT, and CPU utilization charts for all six algorithms.

4. Results and Discussion

Key Outcomes

  • All six scheduling algorithms are available independently.
  • Preemptive schedulers preserve remaining burst time correctly.
  • Idle intervals are represented in timelines and Gantt charts.
  • Process-level CT, TAT, WT, and WTT values are displayed after simulation.
  • Random datasets can be previewed, edited, regenerated, and confirmed before insertion.
  • Comparison results identify workload-specific winners rather than claiming a universal best algorithm.

Comparison with Objectives

The implementation meets the primary objectives. Assignment-style validation produced the expected average waiting and turnaround values: FCFS 15.50/20.50, SJF 10.63/15.63, SRTF 9.75/14.75, Priority NP 11.75/16.75, Priority P 10.50/15.50, and Round Robin 20.88/25.88 for the tested workload.

Challenges and Solutions

ChallengeSolution
Preemption and remaining timeSchedulers split timelines at relevant arrival or quantum events and preserve remaining_time.
Consistent comparisonsThe common Scheduler interface clones every input process for each algorithm.
Duplicate random IDsThe dedicated generator reserves existing and newly generated IDs.
Readable interfaceSimulation, comparison summary, and performance graphs are separated into tabs.
CPU utilization interpretationUtilization is calculated from busy time and elapsed time; it is normally equal across work-conserving algorithms when no context-switch cost is modeled.

Testing Outcome

The project test suite contains 33 passing tests covering models, metrics, all six scheduling implementations, comparison independence and ranking, random generation, invalid inputs, ties, preemption, Round Robin queue behavior, and idle periods. Source and test modules also compile successfully.
